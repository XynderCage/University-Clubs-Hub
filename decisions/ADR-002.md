# ADR-002: Repository port between application service and persistence
- **Status:** Accepted for Phase 2 demonstrator
- **Date:** 30 October 2026
- **Related:** ADR-001; FR1–FR3; BR1; QS1

## Context
UC-01 retrieves verified clubs. Application logic should not couple to a database adapter and needs isolated tests.

## Decision
Introduce a `ClubRepository` port. `ClubService` depends on that stable interface. `SQLiteClubRepository` implements it. The HTTP handler calls the application service and contains no SQL.

## Alternatives
1. SQL in HTTP handler: fewer files but mixes transport, policy and persistence.
2. ORM-specific service code: convenient CRUD but couples use-case logic to ORM and adds dependencies before production framework selection.

## Consequences
Positive: inward dependency direction, isolated tests, replaceable adapter. Negative: extra abstraction/mapping; do not generalize beyond actual need.

## Verification
Unit-test service; integration-test SQLite; verify BR1 for list/detail; inspect handler for absence of SQL.
